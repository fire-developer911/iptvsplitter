🛠️ WHAT THE CODE DOES
═══════════════════════════════════════════════════════════════════════════

REQUEST FLOW
─────────────────────────────────────────────────────────────────────────

1. Client sends request with credentials
   GET /live/user/pass/1.ts?username=alice&password=pwd1

2. Proxy extracts username & password from query params
   username = "alice"
   password = "pwd1"

3. Proxy validates against .env users
   ✓ Check if "alice" exists in users{}
   ✓ Check if password matches
   ✓ Check if not expired

4. If valid, proxy rewrites credentials
   FROM: ?username=alice&password=pwd1
   TO:   ?username=real_user&password=real_pass

5. Proxy forwards to upstream server
   GET http://upstream.com:8080/live/user/pass/1.ts?...

6. Upstream returns response (video, playlist, etc.)

7. Proxy streams response directly to client
   Response piped chunk-by-chunk (no buffering)

8. Client receives video without seeing real credentials
   ✓ Only sees alice/pwd1
   ✓ Never sees real_user/real_pass


ERROR SCENARIOS
─────────────────────────────────────────────────────────────────────────

Missing Credentials?
  └─ 401 Unauthorized: "Missing username or password"

Invalid Username?
  └─ 401 Unauthorized: "Invalid username"

Wrong Password?
  └─ 401 Unauthorized: "Invalid password"

Account Expired?
  └─ 403 Forbidden: "Account expired"

Upstream Down?
  └─ 502 Bad Gateway: "Failed to connect to upstream server"


🔄 MANAGING USERS AFTER DEPLOYMENT
═══════════════════════════════════════════════════════════════════════════

ADD A NEW USER
─────────────────────────────────────────────────────────────────────────
1. Go to Render dashboard
2. Click your service
3. Click "Environment"
4. Add three new variables:
   user_2_user=newclient
   user_2_pass=newpassword
   user_2_exp=31/12/2026
5. Click "Save Changes"
6. Service auto-redeploys (2-3 minutes)
7. New user can now log in immediately


EXPIRE A USER IMMEDIATELY
─────────────────────────────────────────────────────────────────────────
1. Find user_N_exp in Environment
2. Change to past date (e.g., 1/1/2020)
3. Click "Save Changes"
4. That user is rejected on next request (no restart!)


REMOVE A USER
─────────────────────────────────────────────────────────────────────────
1. Delete all three variables (user_N_user, user_N_pass, user_N_exp)
2. Click "Save Changes"
3. User can no longer log in


ROTATE UPSTREAM CREDENTIALS
─────────────────────────────────────────────────────────────────────────
1. Update main_user and main_pass in Environment
2. Click "Save Changes"
3. All clients instantly use new credentials
4. No client-side configuration needed!


📞 TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════════

Problem: Service won't start on Render
Solution:
  1. Go to Render dashboard
  2. Click your service
  3. Go to "Deployments" tab
  4. Click the failed deployment
  5. Scroll to "Build logs"
  6. Look for errors (missing dependencies, syntax errors, etc.)
  7. Fix locally and push to GitHub


Problem: "Invalid username" errors from clients
Solution:
  1. Check .env (or Render Environment) for typos in user_N_user
  2. Make sure variable name is exactly "user_1_user" (not user_1_username)
  3. Check for trailing whitespace
  4. Restart service or update any Environment variable to redeploy


Problem: "Can't connect to upstream" error
Solution:
  1. Verify main_url is correct and reachable
  2. Test locally: curl http://your-upstream-url:8080/
  3. Check if upstream provider is blocking Render's IP range
  4. Verify main_user and main_pass are correct
  5. Check logs: Render dashboard → Logs tab


Problem: Video streams buffer or stall
Solution:
  1. Check upstream server status
  2. Verify Render CPU/memory not maxed (Logs tab)
  3. Try upgrading from Free to Starter tier
  4. Check client's internet connection
  5. Monitor logs for errors


Problem: Service keeps sleeping/restarting
Solution:
  Render Free tier sleeps after 15 minutes.
  Upgrade to Starter plan ($7/month) for always-on service.
